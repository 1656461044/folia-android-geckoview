# 经验教训

这份是从这个项目里提炼出来、**可以迁移到别的项目**的通用教训。
踩坑细节见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)。

---

## 1. 用推断代替核实，是最大的时间黑洞

这个项目里我犯了**四次同类错误**：

| 次数 | 我的推断 | 该核实的事实 | 代价 |
|---|---|---|---|
| 1 | 「Chromium 95 太老跑不动 Folia」 | `dumpsys` 看桥调用 / DOM 是否正常 | 统计了 `?.` 九千处、`color-mix` 八百处，全是白费 |
| 2 | 「62 首歌是小体量，复制没问题」 | `du -sk /sdcard/Music` | 实际 55 个 flac 共 **3.0 GB**，方案整个推翻重做 |
| 3 | 「ref 我命名成 `imp-` 就行」 | 看前端 `startsWith('imported-')` | 删歌功能**静默失效** |
| 4 | 「返回 `track.url` 页面就会用」 | 看前端 `_N()` 怎么拼 URL | 精心设计的 A/B 路由字段**从头到尾没生效** |

共同点：**我有能力核实（源码在手边、`du` 一条命令），也确实部分看过，但在「看起来合理」的地方停手了。**

**规则**：涉及「对方会不会接受我的东西」的判断，一律看消费端代码，不看自己的设计文档。

## 2. 先做对照实验，再下结论

排查「A 应用在设备上不正常」时：

- 同一台车机上**系统浏览器**能正常渲染 Folia 官网 → 证明内核无辜，问题在 APK 自身
- 用 CDP 抓 DOM 证明 JS 逻辑正常 → 排除兼容性

我在这个项目上先断言「Chromium 95 跑不动」，被这两个对照实验完全推翻。

**真正的错误只有一句话**：`NetworkError when attempting to fetch resource`（CORS），
而且只有在加了页面内探针、把**原始错误文本**打出来后才浮现。

---

## 3. 改完没效果，先怀疑缓存

**症状**：改了代码、重新打包、覆盖安装，行为完全没变。

**排查顺序**（按经验命中率排序）：

1. **Service Worker precache**（这个项目真凶）
2. 引擎 HTTP 缓存（固定 origin 尤其容易中招）
3. 你改的文件根本没打进包（`unzip -l` 看一眼）
4. 你改的是 `assets` 里的副本，但运行时读的是另一处

**判据**：日志里打一个版本号，看它有没有随新包变化。这次就是靠
「shim 版本号一直停在最初那版」锁定的。

## 4. 属性劫持：原始描述符必须提前抓一次

一旦用 `defineProperty` 覆盖了原型属性（比如 `HTMLMediaElement.prototype.volume`），
后面代码里再 `Object.getOwnPropertyDescriptor(...)` 现场取「原始」描述符，
**拿到的是你自己的 hook**。

于是 helper 调用 `desc.set` 会兜回自己的 setter，形成自我递归。

**规则**：
- 原始描述符在 `defineProperty` **之前**抓一次，存模块级常量
- getter 也要隔离：劫持后应返回「对方自己的值」，不能返回被变换后的真实值
  （否则对方监听到 change、读回变换值、写回去，又是一次叠加）

**通用形态**：任何「A 改了 B 的读/写，B 又监听 B 的读/写」的场景都有这个陷阱，
音量、透明度、缩放、滚动位置都算。

## 5. 别用「设备品类」推断物理形态

我按 `automotive` 给车机锁了横屏，理由是「车机是固定横屏面板」。
用户直接指出：**车机屏幕可以旋转**。

同类错误还有刘海策略按设备分叉。

**规则**：设备类别只说明「可能有什么能力」，不说明「当前是什么状态」。
默认给最宽的适用范围，只在用户显式选择时收窄。

## 6. 给前端的字段，和前端要的字段，是两件事

设计原生能力时很容易犯的错误：我定义一个漂亮的返回结构，
然后假设前端会照着用。

**实际两次都错**：`track.url` 被忽略、ref 前缀被过滤掉。

**做法**：
1. 先 `grep` 前端 bundle 里目标字段名，看它是**被读取**还是只是摆设
2. 契约以**消费端代码**为准
3. 拿不准就打日志把实际传过去的值打出来

## 7. HTTP 音频流给 WebView / GeckoView，三个必查项

漏一个都可能表现为「无法访问文件」或疑似卡死：

1. **Range 的 `end` 必须解析** —— 探测常用 `Range: bytes=0-0`（只要 1 字节），
   只读 `start` 会把整个文件当响应体发出去
2. **`Content-Type` 按真实格式给** —— 写死 `audio/mpeg` 会让 flac/m4a 走错解码器
3. **探测语义对齐** —— 前端常用 `fetch(url,{headers:{Range:'bytes=0-0'}})` 判可用性，
   `206/200` 判 ok、`404` 判 missing、其它判 blocked；
   路由必须返回**正确的 404**，而不是 200 空响应

在 Android `ContentResolver`（无随机定位）下的实现方式：
**跳读到 `start` 再限长输出**。

## 8. 用真实请求验证自己的实现，比读代码可靠

Range 那个 bug 不是靠猜发现的，是靠**打印实际响应头**发现的：

```
$ printf 'GET /media/X HTTP/1.0\r\nRange: bytes=0-0\r\n\r\n' | nc 127.0.0.1 47831
HTTP/1.1 206 Partial Content
Content-Range: bytes 0-0/34119555
Content-Length: 34119555     ← 应该是 1！
```

一眼看出问题。

**做法**：本地起 HTTP 服务时，用 `nc` / `curl` 直接打自己，比在应用里点来点去快得多。

## 9. 识别「假实现桩」

前端会**真的调用**某些方法，但原生侧留了个「返回假值」的占位：

```java
case "getAdaptiveLayout":
    return new JSONObject().put("enabled", false);   // 假的
```

表现为：设置面板点了没反应、开关状态和实际表现对不上。

**排查**：在 web bundle 里 `grep` 方法名，看它被哪些模块引用、
是**真的 UI 调用**还是**仅能力探测**。

**确认是真调用就必须实现真语义**，顺手把默认值对齐现有观感
（比如自适应布局默认 `true`，因为壳本来就是全屏沉浸式）。

## 10. 异步 UI 功能「点了没反应」的排查顺序

1. **方法没实现 / 返回占位桩**（最常见）
2. **没把 Activity 结果回调转发给等待方**（SAF、相机、文件选择器都吃这个）
3. 权限问题（**往往不是**）

这次用户第一反应是「是不是没索取读写权限」，`pickAudioFolder` 实际是
`return {cancelled:true}` 占位，而 SAF 本身**根本不需要存储权限**。

**把「权限」当第一嫌疑最容易跑偏。**

---

## 11. 容器里桥是同步的，异步回调要自己搭桥

原生桥是「页面 `fetch` 拿同步响应」的模型，而 SAF 是 `startActivityForResult` 异步回调。

**解法**：`CountDownLatch` 让处理 `/__native/call` 的池线程阻塞等用户选完
（超时 300s 兜底），`MainActivity.onActivityResult` 转发给等待方放行。

**不转发就会一直等到超时** —— 表现为「点了没反应」。

---

## 12. 空间与生命周期要想全

用户原话：**「而且在应用里把导入的歌曲文件夹删了，文件也会在私有里存着」**。

不只是「功能能用」，还要问：

- 一份内容会不会存两份？（复制 vs 引用）
- 删了之后，**真正该删的东西删了吗**？（副本、映射、持久授权）
- 卸载应用会清理吗？
- 老版本留下的垃圾谁来扫？

另外删除语义要严格区分归属：**引用系统文件时，只移除引用，绝不删用户原文件。**

---

## 13. 自动化交互的边界

`adb shell input tap` 能做很多事，但**不适合**：

- 系统文件选择器（坐标反复点偏、会误触面包屑）
- 被第三方远控接管的屏幕
- 需要精确落点的一次性操作

这类地方直接请人操作，**说清楚点哪里、期望什么、看哪条日志**，
比自己试五六次快得多。

---

## 14. 交付文档要能自证

写「交给别的 AI 执行」的提示词时，有效的结构：

1. 分模式（只装成品 / 从源码重建），各自独立可粘贴
2. 每步写清**判定标准**与「不满足就停下汇报」，禁止跳步
3. 先安排只读检查，再动真格
4. 明确写出验收串让人能自证
5. 元规则固定三条：参数用实测值不要猜、失败就停不要绕过、做完给简短报告不要反复确认
6. **提示词里的命令必须自己先跑通一遍**
